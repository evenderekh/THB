# THB Site Architecture

**Translator's Hebrew Bible** — a static hexapla at [hebrewbible.dev](https://hebrewbible.dev).  
Six parallel columns per verse: Hebrew (WLC), Greek (LXX), Latin (VUL), English (KJV), Dead Sea Scrolls, and Samaritan Pentateuch.

---

## What It Is

A fully static site — no server, no runtime database. Every page is a self-contained `index.html` baked at build time. Words are clickable; all definitions, morphology, Strong's numbers, and word-frequency data are inlined into each page.

## Aleppo Codex Facsimile Index

`thb.1.3.aleppo.json` is a pre-compiled sorted list of 587 facsimile page entries, one per surviving page of the Keter Aram Tzova facsimile edition:

```json
[
  { "file": 10, "book": "Deuteronomy", "ch_from": 28, "v_from": 17,
    "closing_book": "Deuteronomy", "ch_to": 28, "v_to": 45 },
  ...
]
```

`file` is the facsimile page number (the source filename without extension). The builder uses this to construct a link to the Internet Archive viewer:

```
n = file if file is odd else file − 1
https://archive.org/details/Aleppo_Codex_fascimile_edition/page/n{n}/mode/2up
```

The viewer shows two-page spreads; `n` is the lower page number of the spread (which is the right-hand page in Hebrew reading order). File 010 (`n9`) is the special case: it is the first surviving Aleppo page, sharing a spread with facsimile page 9 which has no Aleppo content.

The Aleppo Codex is missing Genesis through Deuteronomy 28:16 and scattered later sections. MT verse-number cells show a 📜 scroll icon link only when the verse has Aleppo coverage; the icon is absent for unattested verses.

## Per-Tradition Data Files

The master data is split into one JSON file per tradition. Each file contains the full text and morphology for that tradition, keyed by book name:

```json
{ "Genesis": [ {chapter, verses:[{verse, words:[...]}]} ], ... }
```

DSS verses nest words under scroll attestations rather than directly — each verse contains one or more `scrolls` entries (e.g. `"4Q2"`, `"1QIsa-a"`), each with its own word list. DSS word objects carry `surface_full`, `biblical_ref`, and `fragment` fields in addition to the standard set.

Each word object carries: `thb_id` (stable OSID), `surface`, `lemma`, `morph`, `morph_thb`, `consonantal`.

**Morphology fields:**
- `morph` — raw tradition-specific codes, parsed at build time by the tradition's morph parser.
- `morph_thb` — pre-computed morphology dict (`{pos, case, gender, number, ...}`). Authoritative for LXX and VUL. Drives all `data-pos`, `data-case` etc. attributes on the live site.

**Per-tradition rendering:**
- MT: `parse_oshb_morph(morph)` at build time. The leading `H`/`A` language prefix is optional in the data (~35% of tokens omit it).
- LXX: stored `morph_thb` used directly (all 496K Swete words have it).
- VUL: stored `morph_thb` used directly.
- SP: `parse_sp_morph(morph)` at build time. Lemma looked up via `_sp_consonant_index` (see below).
- DSS: `parse_dss_morph(morph)` at build time. Lemma stripped of `_1`/`_2` suffixes, then looked up via `_sp_consonant_index` into MT lexicon.
- KJV: `strongs` field (baked into each word object) drives hover definitions. H853 (את) intentionally omitted.

**LXX book name variations:**
- `"Joshua B"` / `"Judges B"` — Vaticanus recension.
- `"Nehemiah"` — separate top-level key, chapters 1-13.

**Column availability:**
- SP: Torah only (Genesis–Deuteronomy).
- DSS: all books except Esther, 1 Chronicles, 2 Chronicles.

## Lexicons: `thb.1.3.lexicon.json`

One file with three top-level keys, loaded once at build start.

| Tradition | Entries | Key | Fields |
|-----------|---------|-----|--------|
| `mt` | 12,321 | Numeric Strong's code string (e.g. `"1254"`) | `hebrew`, `strongs_id`, `strongs_def`, `bdb_def`, `thb_def` |
| `lxx` | 18,248 | Greek lemma (e.g. `"καί"`) | `lsj_def`, `thb_def` |
| `vul` | 11,704 | Normalized Latin lemma | `ls_def`, `thb_def` |

**Coverage:**
- MT: `strongs_def` ~72%, `bdb_def` ~69.5%, `thb_def` ~76.5%
- LXX: `lsj_def` ~50.5%, `thb_def` ~100%
- VUL: `ls_def` ~52%, `thb_def` ~100%

**Definition formats:**
- `bdb_def`: `(pos) primary: description — • sense • sense …` Senses use `•` bullets separated by `\n`; multiple entries for the same Strong's separated by `\n\n`.
- `lsj_def` / `ls_def`: first 8 glosses joined with `, `.
- `strongs_def`: concise definition from `StrongHebrewG.xml`.

Each page collects only its used lemmas into a compact `{{{LEX_DATA}}}` blob — no network calls at runtime.

## SP / DSS Lemma Lookup (`_sp_consonant_index`)

SP uses no vowel points and no final letter forms (ם→מ, ן→נ, etc.). The builder maintains a reverse consonantal index to connect SP and DSS words to MT Strong's definitions:

- Built at `load_data()` time from numeric entries in the MT lexicon.
- For each MT entry: strip niqqud from the `hebrew` field → normalize final letters → map to Strong's code.
- At render time: apply the same normalization to the SP/DSS lemma → look up → render hover definition.

```python
_FINAL_TO_MEDIAL = str.maketrans('םןךףץ', 'מנכפצ')

def _strip_nikkud(text: str) -> str:
    nfd = unicodedata.normalize('NFD', text)
    stripped = ''.join(
        c for c in nfd
        if not (0x0591 <= ord(c) <= 0x05C7
                or 0x0300 <= ord(c) <= 0x036F)
    )
    return stripped.translate(_FINAL_TO_MEDIAL)
```

Maqaf (U+05BE), paseq (U+05C0), and sof pasuq (U+05C3) are excluded — punctuation, not niqqud. The template's JS `stripHebrewNiqqud` uses the same logic: `[֑-ֽֿׁ-ׂׄ-ׇׅ]`.

Match rate ~63% on content words; unmatched words are typically inseparable prepositions/conjunctions with no standalone lexicon entry.

## Concordance: `backend/concordance/{book}.json`

Strong's frequency data split into one file per book (39 total). Each file:

```json
{
  "schema": "1.3",
  "book": "Genesis",
  "entries": {
    "1": {
      "1": { "H7225": {"Genesis": 51, "Psalms": 6, ...}, ... }
    }
  }
}
```

The builder loads all 39 files at startup into `self.concordance_data` keyed by book name. For each chapter page, it merges all verse entries into a single `{{{WORD_DATABASE}}}` JS object baked into the page.

## Versification: `thb.1.3.versification.json`

The six traditions don't always agree on chapter/verse numbers. `VersificationMapper` handles cross-tradition resolution.

```json
{
  "schema": "1.3",
  "sources": {
    "lxx":        { "license": "CC-BY-SA 4.0", "credit": "Copenhagen Alliance", "data": {...} },
    "vul":        { "license": "CC-BY-SA 4.0", "credit": "Copenhagen Alliance", "data": {...} },
    "kjv":        { "license": "CC-BY-SA 4.0", "credit": "Copenhagen Alliance", "data": {...} },
    "supplement": { "license": "MIT",           "credit": "THB Project",         "data": {...} }
  }
}
```

The `supplement` source covers books the Copenhagen Alliance files don't include. The mapper inverts these maps at build time (MT → tradition); where a verse number differs from MT, a small italic label (e.g. `12:5`) appears in the top-right of that cell.

## The Builder: `thb_builder_fixed.py`

Single Python 3 script (~1,650 lines). All paths are `Path(__file__).parent`-relative.

### `VersificationMapper`

`resolve(tradition, canonical_book, chapter, verse)` → `([(trad_ch, trad_v), ...], display_label)` or `None` for 1:1 mappings.

### `THBSiteBuilder`

```python
THBSiteBuilder(
    backend_dir   = 'thb/backend',
    template_path = 'thb/thb_complete_template.html',
    output_dir    = 'thb/public_html',
)
```

**Key state:**

| Attribute | Contents |
|-----------|----------|
| `self.thb_data` | `{"mt": {...}, "lxx": {...}, ...}` — loaded from 6 per-tradition files |
| `self.mt_lexicon` / `self.lxx_lexicon` / `self.vul_lexicon` | Loaded from `thb.1.3.lexicon.json` |
| `self.concordance_data` | `{book: {ch: {verse: {H…: {Book: count}}}}}` — loaded from `concordance/` |
| `self._page_lex` | Per-page lexicon accumulator, reset each chapter |
| `self._sp_consonant_index` | Consonantal Hebrew → Strong's code |
| `self.aleppo_pages` | Sorted list of Aleppo facsimile page entries, loaded from `thb.1.3.aleppo.json` |

**Key methods:**

| Method | Purpose |
|--------|---------|
| `load_data()` | Loads all backend files; builds SP consonantal index |
| `get_tradition_book_name(book, tradition)` | Maps canonical name to tradition key (e.g. `"Joshua"` → `"Joshua B"` for lxx) |
| `_prev_next_urls(book, chapter)` | Bakes prev/next nav hrefs; wraps at Bible boundaries |
| `build_word_span(word, tradition)` | Renders a single `<span>` with all data attributes |
| `build_combined_verse_row(...)` | Renders one full row of six columns for a verse |
| `build_words_section(book, chapter)` | Renders all verse rows for a chapter |
| `build_chapter_frequency(book, chapter)` | Merges concordance data for a chapter |
| `build_word_database(book, chapter)` | Produces the inlined Strong's frequency JS object |
| `build_page_lexicon()` | Produces the inlined per-page lexicon JS object |
| `build_chapter_page(book, chapter)` | Fills the template; returns complete HTML |
| `generate_sitemap()` | Writes `public_html/sitemap.xml` |
| `build_site()` | Iterates all 39 books × chapters; writes every `index.html` and sitemap |
| `build_search_pages(temp_dir)` | Writes JS-stripped copies for Pagefind |
| `_aleppo_url(book, chapter, verse)` | Range-scans `self.aleppo_pages`; returns archive.org URL or `None` |
| `_aleppo_archive_url(file_num)` | Computes `n` and returns the formatted archive.org URL |

**Morph code parsers** (standalone functions at top of file):

| Function | Handles |
|----------|---------|
| `parse_oshb_morph(code)` | OpenScriptures Hebrew → UD-style dict |
| `parse_lxx_morph(code)` | CATSS Greek → UD-style dict |
| `parse_sp_morph(code)` | SP ETCBC pipe-separated codes. Format: `POS|[VERBFORM|][field=value|…]`. Stem codes use `]X]` bracket notation: `]]`=Qal, `]H]`=Hiphil, `]N]`=Niphal, etc. |
| `parse_dss_morph(code)` | Text-Fabric DSS codes. POS: `subs`=noun, `ptcl`=particle, `adjv`=adjective, `pron`=pronoun, `numr`=numeral, `suff`=suffix |

## Template: `thb_complete_template.html`

Single HTML file. The builder replaces `{{{TAG}}}` placeholders with generated content:

| Tag | Content |
|-----|---------|
| `{{{PASSAGE}}}` | e.g. `"Genesis 1"` |
| `{{{BOOK}}}` | Display book name |
| `{{{BOOK_LOWERCASE}}}` | URL-slug book name |
| `{{{CHAPTER_NUMBER}}}` | Integer chapter number |
| `{{{DOMAIN}}}` | `hebrewbible.dev` |
| `{{{BODY_CLASSES}}}` | CSS classes for absent columns (`hide-sp`, `hide-dss`) |
| `{{{PREV_URL}}}` | URL of previous chapter |
| `{{{NEXT_URL}}}` | URL of next chapter |
| `{{{WORDS}}}` | All rendered verse rows |
| `{{{WORD_DATABASE}}}` | Inlined Strong's frequency data as JS object |
| `{{{LEX_DATA}}}` | Inlined per-page lexicon as JS object |

**`.ms-link`** — the scroll icon link (📜) rendered next to MT verse numbers when Aleppo coverage exists. Styled at `0.8em`, `opacity: 0.35` at rest / `0.85` on hover, opens the Internet Archive facsimile viewer in a new tab.

CSS and JS are fully inline — no external stylesheet or script dependencies (except the Pagefind search widget).

**Fonts** are self-hosted in `/static/fonts/` (7 woff2 subsets). Five fonts in the initial viewport have `<link rel="preload">` hints.

**Nav arrows** are `<a href>` elements with baked hrefs — all 928 pages are crawlable via link-following.

**SEO / accessibility:**
- `<title>`: `{{{PASSAGE}}} | Translator's Hebrew Bible`
- Breadcrumb JSON-LD baked into every page
- Primary content in `<main>`; nav `<select>` elements have `aria-label`

**Definition panel** shows tabs: THB / Strong's / BDB. Only tabs with content are shown.

**`stripHebrewNiqqud(html)`** — used when the "Strip niqqud" toggle is active:
```javascript
function stripHebrewNiqqud(html) {
    return html
        .normalize('NFD')
        .replace(/[֑-ֽֿׁ-ׂׄ-ׇׅ]/g, '');
}
```

## Build

```bash
python thb/thb_builder_fixed.py                              # full build (39 books, 928 chapters)
python thb/thb_builder_fixed.py --mini                       # Genesis 1-3 only
python thb/thb_builder_fixed.py --mini --book Nehemiah --chapters 3
```

**Build sequence:**
1. Load 6 per-tradition JSON files, lexicon, concordance folder, versification; build SP consonantal index
2. For each book/chapter → fill template → write `public_html/<book>/<ch>/index.html`
3. Write `public_html/sitemap.xml` (929 URLs)
4. Copy `genesis/1/index.html` → `public_html/index.html`
5. Write JS-stripped copies to `.search_build/`
6. Run `npx pagefind --site .search_build` → copy `pagefind/` into `public_html/`

## Known Caveats

- **LXX sub-verse letters** (e.g. `2:46b` in 1 Kings) cannot be referenced — the JSON uses sequential integers only. A few LXX additions may align to the wrong MT verse.
- **LXX `lsj_def` coverage** ~50.5% — proper nouns and rare compound verbs. `thb_def` covers ~100%, so every word has at least one definition.
- **MT `thb_def` coverage** ~76.5% — the remaining ~23.5% are structural OSHB tokens (particle codes, prefixed forms) with no definable meaning.
- **1 Kings chapter numbering** — MT ch4=20v / ch5=32v vs KJV ch4=34v / ch5=18v. External versification CSVs using KJV numbering cannot be used directly for MT chapter lookups.
