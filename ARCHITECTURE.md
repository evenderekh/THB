# THB Site Architecture

**Translator's Hebrew Bible** — a static hexapla at [hebrewbible.dev](https://hebrewbible.dev).  
Six parallel columns per verse: Hebrew (WLC), Greek (LXX), Latin (VUL), English (KJV), Dead Sea Scrolls, and Samaritan Pentateuch.

---

## What It Is

A fully static site — no server, no runtime database. Every page is a self-contained `index.html` baked at build time. Words are clickable; all definitions, morphology, Strong's numbers, and word-frequency data are inlined into each page.

## Aleppo Codex Facsimile Index

`thb.1.3.aleppo.json` is a pre-compiled sorted list of 587 facsimile page entries, one per surviving page of the Keter Aram Tzova facsimile edition:

```json
[
  { "file": 10, "book": "Deuteronomy", "ch_from": 28, "v_from": 17,
    "closing_book": "Deuteronomy", "ch_to": 28, "v_to": 45 },
  ...
]
```

`file` is the facsimile page number (the source filename without extension). The builder uses this to construct a link to the Internet Archive viewer:

```
n = file if file is odd else file − 1
https://archive.org/details/Aleppo_Codex_fascimile_edition/page/n{n}/mode/2up
```

The viewer shows two-page spreads; `n` is the lower page number of the spread (which is the right-hand page in Hebrew reading order). File 010 (`n9`) is the special case: it is the first surviving Aleppo page, sharing a spread with facsimile page 9 which has no Aleppo content.

The Aleppo Codex is missing Genesis through Deuteronomy 28:16 and scattered later sections. MT verse-number cells show a 📜 scroll icon link only when the verse has Aleppo coverage; the icon is absent for unattested verses.

## Per-Tradition Data Files

The master data is split into one JSON file per tradition. Each file contains the full text and morphology for that tradition, keyed by book name:

```json
{ "Genesis": [ {chapter, verses:[{verse, words:[...]}]} ], ... }
```

DSS verses nest words under scroll attestations rather than directly — each verse contains one or more `scrolls` entries (e.g. `"4Q2"`, `"1QIsa-a"`), each with its own word list. DSS word objects carry `surface_full`, `biblical_ref`, and `fragment` fields in addition to the standard set.

Each word object carries: `thb_id` (stable OSID), `surface`, `lemma`, `morph`, `morph_thb`, `consonantal`.

**MT punctuation fields** (added in v1.5 via `thb_punct_extractor.py`):

| Field | Type | Meaning |
|-------|------|---------|
| `attach_with_maqqef` | bool | Word is joined to predecessor with maqaf ־ |
| `is_sof_pasuq` | bool | Sentinel token marking verse end (׃) |
| `has_paseq` | bool | Paseq ׀ follows this word |
| `has_reversed_nun` | bool | Nun inversum ׆ follows this word |
| `has_large_letter` | bool | Word contains an oversized scribal letter |
| `has_small_letter` | bool | Word contains a diminished scribal letter |
| `has_suspended_letter` | bool | Word contains a suspended scribal letter |

Verse objects may carry `parashah: "pe"` or `parashah: "samekh"` marking a section break.

**Morphology fields:**
- `morph` — raw tradition-specific codes, parsed at build time by the tradition's morph parser.
- `morph_thb` — pre-computed morphology dict (`{pos, case, gender, number, ...}`). Authoritative for LXX and VUL. Drives all `data-pos`, `data-case` etc. attributes on the live site.

**Per-tradition rendering:**
- MT: `parse_oshb_morph(morph)` at build time. The leading `H`/`A` language prefix is optional in the data (~35% of tokens omit it).
- LXX: stored `morph_thb` used directly (all 496K Swete words have it).
- VUL: stored `morph_thb` used directly.
- SP: `parse_sp_morph(morph)` at build time. Lemma looked up via `_sp_consonant_index` (see below).
- DSS: `parse_dss_morph(morph)` at build time. Lemma stripped of `_1`/`_2` suffixes, then looked up via `_sp_consonant_index` into MT lexicon. Word spans get a `data-sf` attribute holding the raw `surface_full` for client-side damage rendering.
- KJV: `strongs` field (baked into each word object) drives hover definitions. H853 (את) intentionally omitted.

**LXX book name variations:**
- `"Joshua B"` / `"Judges B"` — Vaticanus recension.
- `"Nehemiah"` — separate top-level key, chapters 1-13.

**Column availability:**
- SP: Torah only (Genesis–Deuteronomy).
- DSS: all books except Esther, 1 Chronicles, 2 Chronicles.

## Lexicons: `thb.1.4.lexicon.{mt,lxx,vul}.json`

Three separate files (one per tradition) replace the earlier unified `thb.1.3.lexicon.json`. Each file has a single top-level `"entries"` key:

```json
{ "entries": { "<key>": { <definition fields> } } }
```

| File | Entries | Key | Fields |
|------|---------|-----|--------|
| `thb.1.4.lexicon.mt.json` | 12,321 | Numeric Strong's code string (e.g. `"1254"`) | `hebrew`, `strongs_id`, `strongs_def`, `bdb_def`, `thb_def` |
| `thb.1.4.lexicon.lxx.json` | 18,248 | Greek lemma (e.g. `"καί"`) | `lsj_def`, `thb_def` |
| `thb.1.4.lexicon.vul.json` | 11,704 | Normalized Latin lemma | `ls_def`, `thb_def` |

**Coverage:**
- MT: `strongs_def` ~72%, `bdb_def` ~69.5%, `thb_def` ~76.5%
- LXX: `lsj_def` ~50.5%, `thb_def` ~100%
- VUL: `ls_def` ~52%, `thb_def` ~100%

Each page collects only its used lemmas into a compact `{{{LEX_DATA}}}` blob — no network calls at runtime.

## SP / DSS Lemma Lookup (`_sp_consonant_index`)

SP uses no vowel points and no final letter forms (ם→מ, ן→נ, etc.). The builder maintains a reverse consonantal index to connect SP and DSS words to MT Strong's definitions:

- Built at `load_data()` time from numeric entries in the MT lexicon.
- For each MT entry: strip niqqud from the `hebrew` field → normalize final letters → map to Strong's code.
- At render time: apply the same normalization to the SP/DSS lemma → look up → render hover definition.

```python
_FINAL_TO_MEDIAL = str.maketrans('םןךףץ', 'מנכפצ')

def _strip_nikkud(text: str) -> str:
    nfd = unicodedata.normalize('NFD', text)
    stripped = ''.join(
        c for c in nfd
        if not (0x0591 <= ord(c) <= 0x05C7
                or 0x0300 <= ord(c) <= 0x036F)
    )
    return stripped.translate(_FINAL_TO_MEDIAL)
```

Maqaf (U+05BE), paseq (U+05C0), and sof pasuq (U+05C3) are excluded — punctuation, not niqqud.

Match rate ~63% on content words; unmatched words are typically inseparable prepositions/conjunctions with no standalone lexicon entry.

## Concordance Occurrence Index

Built at `load_data()` time by `build_concordance_data()`. For each tradition, scans every word in the loaded data, derives a canonical lemma key, and records every verse it appears in.

**Lemma key per tradition:**
- MT / SP / KJV: Strong's code prefixed with `H` (e.g. `H7225`)
- DSS: same via `_sp_consonant_index` lookup on the consonantal lemma
- LXX: raw Greek lemma
- VUL: normalized Latin lemma (lowercased, diacritics stripped, macrons removed)

**Output:**
- `self.occurrence_index`: `{tradition: {lemma_key: [(book, ch, verse), ...]}}` — in Bible order
- `self.hapax`: `{tradition: {lemma_key}}` — keys appearing in exactly one verse

**Concordance stub pages** (`build_concordance_stubs()`): one `index.html` per lemma per tradition at `/concordance/{tradition}/{key}/`. Each page groups occurrences by book in `<details>` dropdowns that expand to show the full verse text. An "Expand all" button opens all books at once.

**Filesystem safety:** `_safe_dirname(key)` encodes only the 9 Windows-invalid characters (`\/:*?"<>|`) via percent-encoding, preserving Unicode letters as-is so that URL-decoded paths match directory names under Python's `http.server`.

The word hover panel shows a **concordance link** (→ the stub page) and a **hapax legomenon** badge for single-occurrence lemmas.

## MT Punctuation Extractor: `thb_punct_extractor.py`

Reads the cached OSHB MorphHB XML files (`backend/oshb_cache/`) and adds punctuation fields to `thb.1.3.mt.json`, producing `thb.1.5.mt.json`.

**Source:** OSHB MorphHB XML (same source as the original MT data). Positional matching within each verse is exact — same tokenization, zero alignment problems — with two edge-case fixes:

1. **Morph-split compensation:** OSHB `<w>` elements with multiple morphemes (e.g. `morph="HC/Vqq2ms"`) produce multiple JSON tokens. The extractor counts `/` characters in the morph code to advance the JSON token index correctly so post-word marks (paseq, reversed nun) land on the right token.

2. **Ketiv/qere skip:** OSHB encodes ketiv/qere variants as `<w>` inside `<note>` elements. `root.iter()` visits these but they have no JSON counterpart. They are pre-identified and skipped during word counting.

**Counts (whole Bible):** 2,278 paseq · 9 reversed nun · 3,130 parashah (1,181 pe + 1,981 samekh) · 4 large letter · 3 small letter · 4 suspended letter · 0 mismatches.

```bash
# Re-run if OSHB source changes (XML cached in backend/oshb_cache/)
python thb/thb_punct_extractor.py
python thb/thb_punct_extractor.py --dry-run   # verify without writing
```

## Punctuation Rendering

**MT** — rendered from word-level flags in `thb.1.5.mt.json`:
- `is_sof_pasuq` → `<span class="punct sof-pasuq">׃</span>` (hugs preceding word)
- `has_paseq` → `<span class="punct paseq"> ׀</span>` appended after the word span
- `has_reversed_nun` → `<span class="punct reversed-nun">׆</span>` appended after the word span
- `parashah: "pe"/"samekh"` → `<span class="parashah pe">פ</span>` / `<span class="parashah samekh">ס</span>` prepended to verse
- `has_large_letter` / `has_small_letter` / `has_suspended_letter` → CSS classes on the word span

**LXX / VUL / KJV** — punctuation appears as standalone word tokens (`.`, `,`, `;`, `:`, `!`, `?`, `—`, `–`). `build_word_span()` renders these as `<span class="punct">` elements that hug the preceding word with no space.

**Toggle behavior:** each tradition's "Áa" button calls `stripDiacritics()` which removes all `<span class="punct[^"]*">` and `<span class="parashah[^"]*">` elements before stripping combining marks. `restoreOriginalText()` restores the cached original HTML.

## DSS Damage-Marker Rendering

The Dead Sea Scrolls data uses `surface_full` — a lightly marked-up string encoding physical manuscript damage alongside the Hebrew letters. The builder emits each word's `surface_full` in a `data-sf` attribute; the template parses and renders it at page load.

**`surface_full` sigil inventory:**

| Sigil | Meaning |
|-------|---------|
| `[ ]` | Lacuna brackets — letters inside are reconstructed from context |
| `?` | Single uncertain letter (after the letter) |
| `#` | Single damaged letter |
| `#?` | Damaged and uncertain |
| `##` | Severely damaged |
| `{{ }}` | Scribal cancellation (deleted text) |
| `(^ text ^)` | Supralinear insertion |
| `(<< text >>)` | Ancient correction |
| `(< text >)` | Modern editorial correction |
| `ε` | Placeholder for illegible / missing letter |

**Cross-word bracket state:** lacuna brackets can open in one word and close in a later word. `renderDSSWords()` iterates all `.qumran-word[data-sf]` spans in document order, threading a single `bracketState` boolean across all of them.

**Damage CSS classes:**

| Class | Sigil | Style |
|-------|-------|-------|
| `.dmg-recon` | `[ ]` letter | Dimmed grey — reconstructed |
| `.dmg-unc1` | `?` | Muted gold |
| `.dmg-unc2` | `#` | Amber |
| `.dmg-unc3` | `#?` | Orange |
| `.dmg-unc4` | `##` | Red-orange |
| `.dmg-removed` | `{{ }}` | Struck-through grey |
| `.dmg-supra` | `(^ ^)` | Blue superscript |
| `.dmg-anc` | `(<< >>)` | Muted green |
| `.dmg-mod` | `(< >)` | Muted purple |

The "Áa" damage toggle re-runs `parseWord/tokensToHTML` from `data-sf` (restore) or calls `dssCleanText(sf)` (strip), preserving correct bracket state across the whole column.

יהוה occurrences are detected after cleaning and marked `.tetragrammaton` with a soft gold glow.

## Versification: `thb.1.3.versification.json`

The six traditions don't always agree on chapter/verse numbers. `VersificationMapper` handles cross-tradition resolution.

```json
{
  "schema": "1.3",
  "sources": {
    "lxx":        { "license": "CC-BY-SA 4.0", "credit": "Copenhagen Alliance", "data": {...} },
    "vul":        { "license": "CC-BY-SA 4.0", "credit": "Copenhagen Alliance", "data": {...} },
    "kjv":        { "license": "CC-BY-SA 4.0", "credit": "Copenhagen Alliance", "data": {...} },
    "supplement": { "license": "MIT",           "credit": "THB Project",         "data": {...} }
  }
}
```

The `supplement` source covers books the Copenhagen Alliance files don't include. The mapper inverts these maps at build time (MT → tradition); where a verse number differs from MT, a small italic label (e.g. `12:5`) appears in the top-right of that cell.

## Template: `thb_template_14.html`

Single HTML file. The builder replaces `{{{TAG}}}` placeholders with generated content:

| Tag | Content |
|-----|---------|
| `{{{PASSAGE}}}` | e.g. `"Genesis 1"` |
| `{{{BOOK}}}` | Display book name |
| `{{{BOOK_LOWERCASE}}}` | URL-slug book name |
| `{{{CHAPTER_NUMBER}}}` | Integer chapter number |
| `{{{DOMAIN}}}` | `hebrewbible.dev` |
| `{{{BODY_CLASSES}}}` | CSS classes for absent columns (`hide-sp`, `hide-dss`) |
| `{{{PREV_URL}}}` | URL of previous chapter |
| `{{{NEXT_URL}}}` | URL of next chapter |
| `{{{WORDS}}}` | All rendered verse rows |
| `{{{WORD_DATABASE}}}` | Inlined Strong's frequency data as JS object |
| `{{{LEX_DATA}}}` | Inlined per-page lexicon as JS object |
| `{{{LAYOUT_CTX}}}` | `"torah"`, `"standard"`, or `"nodss"` — drives default column set |

CSS and JS are fully inline — no external stylesheet or script dependencies (except the Pagefind search widget).

**Fonts** are self-hosted in `/static/fonts/` (7 woff2 subsets). Five fonts in the initial viewport have `<link rel="preload">` hints.

**DSS rendering functions** (defined at script scope, called from `DOMContentLoaded`):
- `dssCleanText(sf)` — strips all damage sigils; returns plain consonantal text
- `parseWord(sf, inBracket)` — tokenizes a `surface_full` string into typed tokens, returning `{tokens, bs}` where `bs` is the outgoing bracket state
- `tokensToHTML(tokens)` — maps token types to `<span class="dmg-*">` elements
- `renderDSSWords()` — runs once at page load; iterates all `.qumran-word[data-sf]` spans in document order, threading bracket state

**Sticky scroll padding:** `ResizeObserver` on `.top-bar` keeps the `--top-bar-h` CSS custom property current so `html { scroll-padding-top: var(--top-bar-h) }` always lands anchor links with the verse above the bar.

**SEO / accessibility:**
- `<title>`: `{{{PASSAGE}}} | Translator's Hebrew Bible`
- Breadcrumb JSON-LD baked into every page
- Schema.org WebPage markup

## Deployment

The site is deployed as **seven separate Cloudflare Pages projects** because concordance stub pages (~47,000 files across six traditions) exceed Cloudflare Pages' hard 20,000-file-per-deployment limit.

### Main site

The `concordance/` subdirectory must be excluded — deploying all of `public_html` exceeds the 20K-file limit.

```bash
python -c "import shutil,os; d='public_html_deploy'; os.path.exists(d) and shutil.rmtree(d); shutil.copytree('public_html', d, ignore=shutil.ignore_patterns('concordance'))"
npx wrangler pages deploy public_html_deploy --project-name thb --branch main
python -c "import shutil; shutil.rmtree('public_html_deploy')"
```

Deploy the full `public_html/` tree (chapter pages, static assets, search index). The concordance subdirectories are **not included** in this project — they are deployed separately.

```bash
npx wrangler pages deploy public_html/concordance/mt  --project-name thb-concordance-mt  --branch main
npx wrangler pages deploy public_html/concordance/lxx --project-name thb-concordance-lxx --branch main
npx wrangler pages deploy public_html/concordance/vul --project-name thb-concordance-vul --branch main
npx wrangler pages deploy public_html/concordance/sp  --project-name thb-concordance-sp  --branch main
```

**Build sequence (full + concordance):**
1. Load 6 per-tradition JSON files, 3 split lexicons, concordance folder, versification, Aleppo index; build SP consonantal index
2. `build_concordance_data()` — scan all traditions, build occurrence index and hapax set
3. For each book/chapter → fill template → write `public_html/<book>/<ch>/index.html`
4. Write `public_html/sitemap.xml`
5. Copy `genesis/1/index.html` → `public_html/index.html`
6. `build_concordance_stubs()` — write one page per lemma per tradition under `public_html/concordance/`

## Known Caveats

- **LXX sub-verse letters** (e.g. `2:46b` in 1 Kings) cannot be referenced — the JSON uses sequential integers only. A few LXX additions may align to the wrong MT verse.
- **LXX `lsj_def` coverage** ~50.5% — proper nouns and rare compound verbs. `thb_def` covers ~100%, so every word has at least one definition.
- **MT `thb_def` coverage** ~76.5% — the remaining ~23.5% are structural OSHB tokens (particle codes, prefixed forms) with no definable meaning.
- **DSS concordance key collisions** — DSS lemma lookup goes through the consonantal index (~63% match rate); unmatched words use the raw lemma as the key.
- **1 Kings chapter numbering** — MT ch4=20v / ch5=32v vs KJV ch4=34v / ch5=18v. External versification CSVs using KJV numbering cannot be used directly for MT chapter lookups.
